Architecture

One VPS hosts everything server-side. Caddy is the only public entry point and gets HTTPS certificates automatically. Supabase and PowerSync listen on 127.0.0.1 only, so they are never exposed directly.

Writes from devices go to the Supabase API, which checks permissions in Postgres. PowerSync streams each user's rows back down to their devices. The repo holds everything except secrets: deploy/ (server config), supabase/migrations/ (database), src-tauri/ (Windows) and eas.json (mobile builds).

Before you start

On the VPS

  • Oracle Cloud VPS, ARM (Ampere) or x86. At least 4 GB RAM for Supabase (8 GB recommended) plus about 1 GB for PowerSync.
  • Docker Engine with Compose v2.24+ (docker compose version), git and Caddy, already installed.
  • SSH access as a user that can run docker.

On your PC

  • Node 22 and a clone of the repo with npm install done.
  • For the Windows installer: Rust (stable). Visual Studio Build Tools are recommended (see Troubleshooting).
  • A domain you control, plus a free Expo account for mobile builds.
01

DNS and firewall

Where: DNS provider + Oracle Cloud console

Create three A records pointing at the VPS public IP:

  • app.example.com: the web app
  • api.example.com: the Supabase API and Studio dashboard
  • sync.example.com: PowerSync

In Oracle Cloud, open the VPS subnet's security list and allow inbound TCP 80 and 443 (Caddy needs both). Do the same in the VPS firewall if one is active. Never open 8000, 8080 or 5432.

From your PC, nslookup api.example.com returns the VPS IP for all three names.
02

Install Supabase

Where: VPS

The setup script downloads the official self-hosted Supabase files (pinned version) to ~/myrooms/supabase, generates all secrets, and keeps Supabase's ports private to the VPS.

git clone <repo-url> ~/myrooms/app
cd ~/myrooms/app/deploy
sh supabase/setup.sh
VPS
Those Supabase files hold the secrets, so they live outside the repo and are never committed.

04

Caddy

Where: VPS · blocks in deploy/caddy/Caddyfile.example

Create the web app folder, add the three site blocks to the VPS Caddyfile with your real domains, then reload Caddy.

sudo mkdir -p /var/www/myrooms && sudo chown $USER /var/www/myrooms
VPS
app.example.com {
	root * /var/www/myrooms
	encode zstd gzip
	try_files {path} /index.html
	file_server
	@hashed path /_expo/static/* /@powersync/*
	header @hashed Cache-Control "public, max-age=31536000, immutable"
	header /index.html Cache-Control "no-cache"
}

api.example.com {
	reverse_proxy localhost:8000
}

sync.example.com {
	reverse_proxy localhost:8080 {
		flush_interval -1
	}
}
Caddyfile
sudo systemctl reload caddy
VPS
If Caddy runs in Docker, attach it to the supabase_default and myrooms-powersync_default networks, mount /var/www/myrooms, and proxy to kong:8000 and powersync:8080 instead.
Opening https://api.example.com shows a padlock and asks for the Studio login.
05

Apply the database migrations

Where: your PC (through an SSH tunnel), then VPS

Migrations in supabase/migrations/ are pushed from your PC through an SSH tunnel, so Postgres never needs a public port. POOLER_TENANT_ID and POSTGRES_PASSWORD are in ~/myrooms/supabase/.env.

# Terminal 1: keep this open
ssh -N -L 54329:127.0.0.1:5432 <user>@<vps-ip>
PC
# Terminal 2: from the repo root
npx supabase db push --db-url "postgresql://postgres.<POOLER_TENANT_ID>:<POSTGRES_PASSWORD>@127.0.0.1:54329/postgres"
PC

Then give the PowerSync database role a password (once per server) and confirm logical replication is on:

docker exec -it supabase-db psql -U postgres -c "alter role powersync_role with password '<new-random-password>';"
docker exec -it supabase-db psql -U postgres -c "show wal_level;"   # must print: logical
VPS
In Studio → Table editor, the organizations, branches, memberships, member_branches, invitations, station_types, stations, rate_rules, packages and audit_log tables exist.
06

Install PowerSync

Where: VPS · folder deploy/powersync

Fill in .env: the powersync_role password from step 5, plus a storage password and an admin token (generate each with openssl rand -hex 32).

cd ~/myrooms/app/deploy/powersync
cp .env.example .env && nano .env
docker compose up -d
docker compose logs -f powersync   # replication starts, no errors
VPS
curl https://sync.example.com/probes/liveness answers successfully.
07

Point the app at the VPS

Where: your PC · file .env.local in the repo root
EXPO_PUBLIC_SUPABASE_URL=https://api.example.com
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<from "sh run.sh secrets">
EXPO_PUBLIC_POWERSYNC_URL=https://sync.example.com
EXPO_PUBLIC_APP_URL=https://app.example.com
.env.local

Run npm run web. These values are built into the app, so any change needs a rebuild.

Then check the whole flow:

  1. Create account, open the confirmation email, then Sign in.
  2. Create organization (name + first branch). The home screen shows the branch and the Sync card shows Online.
  3. Offline test: switch Wi-Fi off, go to Settings → Branches → Add branch. "Waiting to upload" becomes 1. Switch Wi-Fi on: it drops to 0 and the branch appears in Studio → branches.
  4. Settings → Staff → Invite a second email as Cashier for one branch. Sign in with that email in another browser: the invitation is on the welcome screen. Join it.
  5. As the owner: Settings → Station types & prices → add a type (e.g. PS5 Room, 4 players), a base price, a peak price (18:00–24:00, priority 10) and a 3-hour package. Then Settings → Stations → add 3 stations at once and put one in maintenance.
  6. Settings → Price preview: 17:00 to 19:30 should cost 1 hour at the base price plus 1.5 hours at the peak price.
The cashier sees only their branch and no Staff or Branches settings, sees the prices read-only, and can't add stations. The owner sees every branch and all staff. The new stations show on the cashier's device.
07b

Invitation emails (Edge Function)

Where: VPS · folder supabase/functions/invite-staff

The app's Invite button calls the invite-staff function. It saves the invitation and emails people who don't have an account yet. Without it, invitations still work, but nobody is emailed (the app says so).

mkdir -p ~/myrooms/supabase/volumes/functions/invite-staff
cp ~/myrooms/app/supabase/functions/invite-staff/index.ts ~/myrooms/supabase/volumes/functions/invite-staff/
cd ~/myrooms/supabase && docker compose restart functions
VPS
Invite a new email from Settings → Staff: the app says the invitation was emailed, and docker compose logs functions shows no errors.

Publish the web app

Where: your PC → VPS
npm run build:web                                         # → dist/
rsync -az --delete dist/ <user>@<vps-ip>:/var/www/myrooms/
PC
No rsync on Windows? Use scp -r dist/* <user>@<vps-ip>:/var/www/myrooms/, or run the rsync from WSL.
https://app.example.com shows the sign-in page; after signing in, the Sync card shows Online.
09

Build the Windows app

Where: your PC or GitHub Actions

Locally (uses .env.local; EXPO_PUBLIC_APP_URL makes password-reset emails sent from Windows link to the web app):

npm run desktop:build
# installer: src-tauri/target/release/bundle/nsis/MyRooms_<version>_x64-setup.exe
PC

From GitHub: add the four EXPO_PUBLIC_* values (including EXPO_PUBLIC_APP_URL) as repository Variables (Settings → Secrets and variables → Actions → Variables). The "Windows desktop build" workflow runs on pushes to dev and main, or by hand, and uploads the installer as a build artifact.

The installer isn't code-signed until Phase 10, so Windows SmartScreen shows a warning ("More info" → "Run anyway").
The installed app opens on the sign-in page; after signing in, its Sync card shows Online.
10

Build the Android and iOS apps

Where: your PC → EAS cloud builds

Phone builds run on EAS (Expo's build service). The offline database uses native code, so the app needs these builds and won't open in Expo Go.

npx eas-cli login
npx eas-cli init                # links the project, once

# Backend URLs for cloud builds (once per environment: development, preview, production)
npx eas-cli env:create --environment development --name EXPO_PUBLIC_SUPABASE_URL --value https://api.example.com --visibility plaintext
npx eas-cli env:create --environment development --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY --value <key> --visibility plaintext
npx eas-cli env:create --environment development --name EXPO_PUBLIC_POWERSYNC_URL --value https://sync.example.com --visibility plaintext

npx eas-cli build --profile development --platform android   # installable APK
npx eas-cli build --profile development --platform ios       # needs an Apple Developer account
PC
The build installs on a phone and opens on the sign-in page. After signing in, the Sync card shows Online and branches created on the web show up on the phone.

Updating and backups

When this changesDo this
New SQL migrationRepeat step 5 (supabase db push through the tunnel)
Sync rulesOn the VPS: cd ~/myrooms/app && git pull, then docker compose restart powersync in deploy/powersync
Edge FunctionRepeat step 7b
App code (web)Repeat step 8
App code (Windows / mobile)Rebuild (steps 9 and 10) and reinstall
Supabase versionFollow the official upgrade notes, using sh run.sh / update.sh in ~/myrooms/supabase

Database files live in ~/myrooms/supabase/volumes/db/data. Until automated backups arrive in Phase 9, run a nightly dump (for example from cron):

mkdir -p ~/backups
docker exec supabase-db pg_dump -U postgres -Fc postgres > ~/backups/myrooms-$(date +%F).dump

Troubleshooting

SymptomFix
Windows build fails with windres: preprocessing failedThe Rust GNU toolchain can't handle a space in the project path. Install Visual Studio Build Tools and run rustup default stable-msvc, or build with CARGO_TARGET_DIR set to the folder's short path: export CARGO_TARGET_DIR="$(cygpath -d "$PWD/src-tauri")\\target" (Git Bash).
PowerSync log: PSYNC_S2105 missing claim audservice.yaml must keep audience: ['authenticated'].
PowerSync log: PSYNC_S2101 no matching keyCheck PS_SUPABASE_JWKS_URI in .env, and that sh utils/add-new-auth-keys.sh ran during setup. Then sign out and back in on the device.
PowerSync can't reach dbRun docker network ls and set SUPABASE_DOCKER_NETWORK in deploy/powersync/.env to Supabase's network name.
Sign-in page says "server is not configured"The EXPO_PUBLIC_* values were not set before the build. Set them and rebuild.
No confirmation or reset emails arriveCheck the SMTP_* values and docker compose logs auth. Local development: emails appear in Inbucket at http://localhost:54324.
Email link opens "link is invalid or has expired"Links work once and expire. Also check the app URL is in ADDITIONAL_REDIRECT_URLS (otherwise Supabase sends people to SITE_URL).
Signed in, but stuck on "Loading your data…"PowerSync isn't reachable or rejects the token: see the PSYNC_* rows above and docker compose logs powersync.
Caddy has no certificateDNS isn't pointing at the VPS yet, or ports 80/443 are closed in the Oracle security list.
